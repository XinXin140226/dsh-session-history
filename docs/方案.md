# dsh-session-history 方案

面向使用者的聊天记录迁移插件。导入 DeepSeek 官方导出的聊天包，导出 DSH 里的会话。

版本：0.2 框架定稿
日期：2026-11-19

## 0 一句话概括

把导出包里的每个会话翻译成一个真正的 DSH 会话，通过 DSH 自己的持久化接口写进会话存储。导出复用官方同款 Markdown 与 zip，后台执行。纯 JavaScript，无原生模块，无构建步骤，手机和电脑装同一份包。

## 1 设计目标

使用面广，任何一条内部结构变化都不能让插件崩掉，只能降级。

具体要求：

- 不碰 DSH 私有文件格式。不手写 zstd 帧，不直接改 profile 配置，只通过 context 服务调用。
- 纯函数优先。解析、映射、计划、报告四层与 DSH 解耦，可以在没有 DSH 的机器上单独跑测试。
- 默认零运行时依赖。可选加速库缺失时自动退回内置实现。
- 全程离线。不发任何网络请求，不做遥测，不读与任务无关的文件。
- 性能随设备自适应，不写死参数。

## 2 分层结构

```
dsh-session-history/
  index.js            Host 侧入口。注册服务、路由、后台任务
  client.js           Client 侧入口。设置页、清单、进度条
  lib/
    zip/              零依赖 zip 读取（中央目录加 inflateRaw）
    deepseek/         导出包解析，产出归一化中间模型
    images/           图片提取与适度压缩
    map/              DeepSeek 片段到 DSH 事件的纯函数
    plan/             导入计划：勾选、去重、时间策略
    store/            幂等映射表、锁、进度状态
    report/           统计与错误汇总
    caps/             能力探测、探针、设备分档
  locale/             中英文案
  scripts/
    lint-copy.mjs     文案黑名单扫描
    selftest.mjs      纯函数自测
  docs/
```

分层原则：lib 下面的东西不认识 DSH，只处理数据。index.js 负责把 DSH 的服务喂给 lib，把结果写成会话。client.js 只做界面，不碰存储。

这样拆的好处是主要风险点全部落在纯函数层，可以在电脑上反复跑测试，不用每次都装插件试。

## 3 兼容性设计

这一节是重点，用户多，坏一条就全坏。

### 3.1 不做硬性版本门禁

不在 package.json 里写死 engines.dsh 范围。硬门禁会让旧版或新版用户直接装不上，比功能降级严重得多。

改成运行时能力探测：启动时检查需要的服务在不在，缺哪个就关掉对应功能，并在界面里说明原因，而不是抛错。

### 3.2 能力探测与探针

激活顺序：

1. 检查 `ctx.sessionPersistence` 是否存在。没有则导入功能不可用，只保留导出。
2. 检查 `ctx.sessionQuery` 是否存在。没有则导出功能不可用。
3. 跑一次探针：合成一个最小会话，写入三条事件，用读句柄回读，校验通过则记住这一版的事件形状；不通过则按降级表逐级减少字段再试。
4. 探针结果缓存到插件数据目录，同一 DSH 版本不重复跑。

探针在独立的临时 profile 里跑，不碰用户真实的会话存储。

### 3.3 只发射白名单事件

导入只发这七种事件：

`user/message`、`assistant/message`、`turn/start`、`turn/end`、`step/start`、`step/end`、`session/title`

这七种是核心渲染需要的，跨版本最稳定。其余事件一律不发。

需要携带的附加信息（原始会话 id、来源、导入时间）全部写进插件自己的映射表，不进会话日志。理由：日志里放非标准事件会被旧版本读取时拒绝，这是硬不兼容。

图片引用是唯一的例外，走第八节的独立通道，探针失败时整个通道自动隐藏。

### 3.4 单会话事务与失败隔离

每个会话独立完成：建头、灌事件、落盘、收尾。任何一个会话失败只记录原因并继续下一个，不中断整批，不影响其他会话。

### 3.5 UI 座位降级链

界面座位按优先级注册，前一个不存在就退到下一个：

1. `settings.section`，独立设置页
2. `settings.plugins.tab`，插件设置页里的一个标签
3. 都不存在则只保留 Host 能力，界面不显示

侧栏入口同理，`sidebar.panellist` 不存在就不注册，不影响功能。

### 3.6 未知字段一律不发射

映射层只输出明确列出的字段。导出包里多出来的字段（例如思考耗时、站点图标、token 用量、搜索 stage）全部丢弃，绝不透传。这是保证能过校验的根本规则。

### 3.7 图片通道独立开关

图片导入涉及 DSH 附件存储的内部格式，版本敏感性最高。它与文本导入完全隔离：单独探测、单独开关、失败单独降级为文件名占位。图片通道出任何问题都不影响文本导入。

### 3.8 首次导入的保险

首次导入前，把 DSH 会话存储目录整体做一次快照备份，放到插件数据目录。备份前检查体积，超过 200 MB 时先提示用户确认。备份失败则拒绝导入并说明原因。

备份只做一次，之后靠幂等表与失败隔离。卸载插件不影响已导入的会话，它们本来就是 DSH 自己的会话；备份文件保留，用户可以自行处理。

## 4 自适应性能

### 4.1 设备分档

启动时探测三项：平台（Android 容器或桌面）、CPU 核数、可用内存。容器里读到的值取系统值与容器限制里较小的那个，Android 上按保守取。

| 档位 | 判定 |
|---|---|
| 低 | 核数不超过四，或可用内存低于 1.5 GB |
| 中 | 其余情况的默认档 |
| 高 | 桌面且核数不少于八且可用内存高于 4 GB |

### 4.2 档位参数

| 参数 | 低 | 中 | 高 |
|---|---|---|---|
| 会话写入并发 | 1 | 2 | 4 |
| 事件批大小 | 120 | 200 | 400 |
| 进度推送节流 | 200 毫秒 | 100 毫秒 | 50 毫秒 |
| 清单每页条数 | 60 | 100 | 200 |

zip 解压一律走异步，不阻塞事件循环，这一条不分档。

### 4.3 运行时反馈调节

导入开始后统计前二十个会话的单个耗时。持续超过三百毫秒自动降一档，存储写入明显变慢时同时收小批大小。运行时只降不升，避免来回抖动。

可用内存低于警戒线时强制降到低档，并把批大小再收一半。

### 4.4 用户覆盖

设置里提供四选：自动（默认）、低、标准、高。手动选定后不再运行时调节，只保留内存警戒线的强制保护。

### 4.5 zip 随机访问

打开文件描述符，扫描文件尾部定位中央目录，只读中央目录。按需读单个条目的压缩字节，解压到 Buffer，解析完释放。

不把 220 MB 整包读进内存。内存峰值取决于最大单个会话（2.9 MB，解析后约 8 MB），与总包大小无关。支持 ZIP64。

可选加速：装了 fflate 就用它，没装自动退回内置的 inflateRaw 实现。

### 4.6 清单先行

第一步只读 `chat_session_index.json`，391 KB，两万条以内毫秒级。用它渲染勾选清单。

清单按更新时间倒序，每页一百条（按档位），顶部搜索框。手机上一次渲染一千多行会卡顿，分页是硬要求，不是优化项。

用户勾选后才读对应的会话文件。

### 4.7 写路径

单会话内部：事件数组按批写入，一次 flush 落盘。会话之间按档位并发，每个会话结束让出事件循环。

### 4.8 幂等表

插件数据目录里维护一份追加写的映射表，记录原始会话 id 到 DSH 会话 id。启动时一次读进内存，查表 O(1)。

作用有三个：重复导入直接跳过；中途取消后可以续跑；导入结果可回溯。

映射表用追加写加逐行校验，最后一行残缺时自动丢弃。

### 4.9 预期指标

| 项目 | 目标 |
|---|---|
| 打开清单 | 1 秒内 |
| 单会话解析加写入 | 20 到 80 毫秒 |
| 全量 1992 个，手机 | 3 到 8 分钟 |
| 全量 1992 个，电脑 | 1 到 3 分钟 |
| 进程内存峰值 | 60 MB 以内 |
| 文本磁盘占用 | 30 到 45 MB |
| 图片磁盘占用（开启时） | 40 到 60 MB |

文本数字来自实测：导出包正文 45.1 MB，压缩后 19.9 MB，DSH 用 zstd 会更好一些，加上事件信封开销后落在 30 到 45 MB。附件原始约 79 MB，适度压缩后按 40 到 60 MB 估。

## 5 数据映射

| DeepSeek 导出 | DSH 会话事件 | 说明 |
|---|---|---|
| 会话 title | `session/title` | 原样保留 |
| 用户 REQUEST | `user/message` 文本块 | 同一条消息多个 REQUEST 按段落合并 |
| THINK | `assistant/message` 的 reasoning 块 | 原生折叠展示 |
| RESPONSE | `assistant/message` 文本块 | 最终输出 |
| 一问一答 | 一对 `turn/start` 与 `turn/end` | 内部套 `step/start` 与 `step/end` |
| inserted_at | 事件时间与会话创建时间 | 保留原始时间 |
| TOOL_SEARCH 等检索片段 | 一行摘要 | 见下 |
| FILE 图片附件 | 附件引用 | 实验性，见第八节 |
| FILE 非图片附件 | 只留文件名占位 | |
| CONTENT_RISK 等提示片段 | 丢弃 | 无信息价值 |

检索片段默认压成一行，放在该轮回复末尾，例如：

```
（检索 2 次 · 打开 3 页：api.github.com 等）
```

设置三档：一行摘要（默认）、检索词列表、不显示。不写网页摘录，不写站点图标，导出 Markdown 同样只留这一行。

映射规则：

- 一条助手消息里 THINK 和 RESPONSE 可能交替多次，按原始顺序合并进同一个 `assistant/message` 的 content 数组。
- 只有思考没有回复的助手消息，产出只含 reasoning 块的 `assistant/message`。
- 思考块上的耗时字段不写入，DSH 侧没有对应字段。
- 用户消息里的文件占位写在正文末尾，一行一个文件名。

## 6 隐私处理

`user.json` 整份不读。以下内容一律不写入 DSH 日志：用户 id、邮箱、手机号、第三方授权信息、头像链接、token 用量、各类状态开关、原始会话 uuid。

原始 id 只存在插件自己的映射表，用于去重与续跑，不出现在会话内容里。

导入完成后不保留原始导出包的任何副本。

## 7 后台任务

导入与导出共用同一套后台机制，都在 Host 侧执行，都不挡界面。

- 侧栏会话列表区域挂一条细进度条，显示已完成数与总数，导入导出共用。
- 点开可以看到当前正在处理的会话标题、成功数、跳过数、失败数与失败原因。
- 支持取消。取消后已完成的保留，靠映射表续跑。
- 进度推送按档位节流。
- 同一时间只允许一个任务，用数据目录里的锁文件保证。

导出完成后弹一条通知，说明文件位置。导出写临时文件，边压边落盘，完成后交给浏览器下载，内存不随总量增长。

## 8 图片导入（实验性）

首版包含，界面与设置均带「实验性」标识，说明可能随 DSH 版本失效。

前置调查：摸清 DSH 附件存储的目录结构与消息里的图片引用格式（`image/offload` 事件与附件引用字段），探针验证通过后才启用。

流程：

1. 勾选实验性开关后，提取 zip 内 `_files` 目录的图片，按 FILE 片段里的 `export_path` 对应到消息。
2. 按探测到的存储格式写入附件库。
3. 消息内容里挂附件引用，客户端原生渲染。

压缩规则：长边超过 2048 像素或单张超过 2 MB 才重编码，长边压到 2048，质量八成五左右，小图原样存。目标是从 79 MB 压到 40 到 60 MB。

失败处理：单张失败不阻断会话导入，占位符里保留原文件名，汇总里单列一项。

默认值：不勾选。导入不可撤销，实验性功能的失败模式最不可控，想用的人显式打开。

如果用户在导入的会话里继续聊天，图片会占用模型上下文，设置项的说明文字里写明这一点。

## 9 导出设计

单个会话：如果官方 `dsh-session-log-export` 在，复用它已有的 Markdown 格式与下载能力。不在则用 `sessionQuery.readSession` 自己拼同样的 Markdown。

批量导出：列表带勾选，可单选可多选可全选。产物是一个 zip，内含每个会话一个 Markdown 文件，加一个清单文件记录导出时间与会话列表。

zip 写入用内置的 deflateRaw 加手写中央目录，约一百多行，零依赖，边写边落临时文件。

思考过程默认包含，用折叠块包住，收起来不占版面。设置里可关。

## 10 界面

设置里一页，标题「聊天记录迁移」。侧栏脚部一个入口图标直达。

页内结构，按使用频率从上到下：

导入。选文件、清单勾选、预览一个会话、开始、进度、结果统计。

导出。会话列表勾选，后台导出。

图片导入（实验性）。开关加说明，默认关。

高级（默认折叠）。性能档位、时间策略、来源说明开关与内容、检索摘要档位。

常用项放上面，高级项折叠，避免一页全是开关吓退普通用户。每个开关带一句说明，说明里写清改动会影响什么。

预览步骤：勾选之后先转出第一个会话，在界面里展示渲染效果，确认后才放行批量。

配色只用 `--dsw-alias-*` 系列与 `--dsw-specific-sidebar-fill`，浅色深色自动跟随，不写死任何颜色值。

文案规范：短句，不用破折号，不用夸大体验的营销词与空泛形容词（完整清单内置在扫描脚本里），不堆 emoji。构建前跑黑名单脚本，不过就不打包。

## 12 验证计划

顺序固定，前一步不过不进下一步。

1. 纯函数自测。用真实的导出包跑 zip 读取，校验条目数、抽查三个会话的解析结果与映射结果。
2. 探针。在临时 profile 里合成最小会话，写入后回读，确认能过格式校验。
3. 附件存储调查。摸清目录结构与引用格式，探针验证一张小图。
4. 单会话实装。导入一个会话，在 Web UI 里打开，确认侧栏可见、标题正确、思考折叠正常、回复正常。
5. 图片实装。导入一个带图会话，确认显示、压缩比、失败占位。
6. 浅色深色各看一遍。
7. 性能实测。用全量包跑一次，记录耗时与内存，与第 4.9 节指标对照。
8. 取消与续跑。中途取消再启动，确认不重复导入。

验证只用少量样本会话，用户当前的聊天记录不导入。

## 15 预设与联网搜索

导入的会话要能继续聊，而且默认带联网搜索，否则核心价值就丢了。

官方的 minimal 预设不含 `tool-web`（联网搜索与网页打开工具），standard 含。用户观察到导入了聊天记录后默认落在极简模式，属实。

做法：插件包自带一个专用预设行，内容是 minimal 的工具集加 `@deepseek-ai/dsh-tool-web`。导入会话时把它的 id 写进会话头的 `agentPreset` 字段，恢复对话时 DSH 按记录的预设组装工具。

设置里一个开关，默认开：

- 开：导入会话记录搜索版预设
- 关：导入会话记录与官方 minimal 相同的工具集，不带搜索

两个注意点：

- 开关只影响之后导入的会话。已导入会话的预设记录在各自的日志里，不改。用户也可以在任何会话里手动切换预设。
- 预设行随插件安装与卸载。插件卸载后，已导入会话记录的预设 id 不再存在，恢复时按 DSH 的回退策略落到默认预设。工具还在，只是工具集可能变化。此行为写入 README 说明。
- 联网搜索本身需要用户在官方设置里配置搜索接口，插件不代管密钥。

## 16 不做的事

- 不改 DSH 的配置文件，不动 profile 的 package.json 与 patch 文件。
- 不伪造工具调用卡片。
