# 验证记录

日期：2026-11-20 凌晨（M1 探针与 M2 纯函数层自测）
环境：DSHA 容器内 DSH 0.2.2-rc.1，Node v24.19.0，Linux（proot）

## 探针一：持久化写入回读（通过）

方法：独立 Cordis 运行时挂真实 `@deepseek-ai/dsh-session-persistence-jsonl` 后端，压缩 zstd，根目录 /tmp/probe/sessions-root。合成头部加七条白名单事件，写入、落盘、回读。

结果：append 通过，read 通过（7 条，state shared-frozen），后端 list 可见，物理日志落在 `--tmp-probe--/session-probe-…/session.v4.jsonl.zstd`，目录布局与真实会话一致。

## 探针二：事件必填字段（全部确认）

逐条来自真实校验器源码与失败信息：

- 头部：`version` 必须为 4；`id` 与会话一致；`createdAt` 非负安全整数；`isSeeded` 必填布尔；`cwd` 可省但给就必须是绝对路径；`agentPreset` 可选字符串。
- 五种 surface 事件（含 `user/message`、`assistant/message`）必须带 `surfaceOp: 'append'`。
- `user/message`：`data` 本身就是消息，须有非空字符串 `id`、`role: 'user'`、`source.kind` 非空字符串、`content` 数组。
- `assistant/message`：`data.message` 须有非空字符串 `id`、`role: 'assistant'`、`source = { kind: 'model', provider 非空, model 非空 }`、`content` 数组。
- `seq` 从 0 起连续，缺号或跳号直接拒绝。
- turn 与 step 有生命周期关系校验：`turn/end` 前必须没有未关闭的 step（由 dsh-session-format-v3-to-v4 的 Relationships 检查）。
- 事件数据必须无损 JSON：任何 undefined 属性会被拒绝（自测踩过，映射层已加压缩保险）。
- 未知事件类型被拒，除非标 `ignorable: true`。本插件不发白名单外事件。

## 探针三：附件存储（通过，走服务路径）

- 存储：`~/.dsh/attachments/v1/objects/<两位前缀>/<64 位 sha256>`，对象名即字节 sha256，实测一致（样本为 JPEG）。
- 写入不手放对象：官方 `ctx.attachments.saveImage({ data, mediaType, name? })` 返回持久引用；引用形状 `{ attachmentId, mediaType, bytes, width, height, name?, originalDimensions? }`；消息内块 `{ type: 'image', attachment: 引用 }`。
- 批量限制（每条消息张数与总字节）由存储层强制，导入器压缩管道只需满足其阈值。
- 图片通道未做写入实测（按方案默认关，留待用户显式开启后验证）。

## 自测：解析映射写入全链路（通过）

## 图片通道（通过，服务层实测）

- 附件服务用 `ctx.attachments.saveImage({ data, mediaType, name })`，不手写内容寻址目录。
- 存储层自带归一化：超过 400 万像素或 4 MB 会重编码，本插件不做二次处理，避免自己引入图像库。
- 实测样本「github直链提取（自带代理加速）」两张截图：写入 2 张，失败 0，附件目录 245 KB，消息里生成 `{type:'image', attachment:{attachmentId, mediaType, width, height, bytes, name}}` 块，回读正常。
- 单张失败只记一笔警告，不影响会话导入与文本内容。
- 界面开关默认关，开启后进度里单独统计图片张数与失败数。
